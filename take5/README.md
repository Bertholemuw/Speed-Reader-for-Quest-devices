# Take 5 auto-entry

Imports a Take 5 digital issue, solves the puzzles, and lodges the prize entries
through the magazine's online entry form — on a weekly schedule, unattended.

```
issue.pdf ──▶ parse ──▶ solve ──▶ entry ──▶ ledger
              grids     answers   Playwright  receipts + screenshots
```

## Read this before you turn it on

Are Media (Take 5's publisher) runs these competitions under terms that
disqualify entries "generated by a script, macro or other automated means", and
almost every puzzle is one entry per person. This tool does exactly the thing
those terms describe. That is your call to make, but it is the reason the
defaults are cautious:

- **`dryRun` ships `true`.** Forms are filled and screenshotted, never submitted,
  until you change it deliberately.
- **The ledger is checked before every entry**, so the same puzzle is never
  lodged twice — not after a crash, not after a double-fired cron.
- **Entries go one at a time**, spaced by `delayBetweenEntriesMs`, so a weekly
  run never arrives as a burst.
- **Low-confidence answers are held back** rather than guessed at.

## Setup

```bash
cd take5
npm install
npx playwright install chromium     # skip if a Chromium is already provisioned

cp config/profile.example.json  config/profile.json    # your entry details
cp config/settings.example.json config/settings.json
cp config/forms.example.json    config/forms.json      # see "Entry forms" below
cp config/puzzles.example.json  config/puzzles.json    # optional: detection rules
```

`GEMINI_API_KEY` in the environment enables crossword clue answering and trivia.
Everything else — sudoku, wordsearch, code cracker, kriss kross, word wheel —
solves offline with no API key at all.

## Weekly use

Drop the issue PDF into `data/inbox/` and leave the scheduler running:

```bash
npm run schedule     # cron from settings.json, default Tue 08:00 Australia/Sydney
```

Each run imports every PDF in the inbox, solves it, lodges the entries, and
moves the file to `data/processed/` so a re-run cannot double up.

Or drive it by hand:

```bash
npm run cli -- import data/inbox/take5-issue-31.pdf
npm run cli -- solve  take5-issue-31-a1b2c3
npm run cli -- submit take5-issue-31-a1b2c3          # dry run
npm run cli -- submit take5-issue-31-a1b2c3 --live   # actually enters
npm run cli -- run --live                            # the whole inbox
npm run cli -- ledger                                # what has been entered
```

## Entry forms

`config/forms.json` maps a form's fields to your profile. Rather than reading
someone else's HTML, point the recorder at the real entry page:

```bash
npm run cli -- record "https://<the entry page>" --headed
```

It inventories every input, guesses the mapping (`#firstName` → `profile.firstName`,
`#answer` → the solved answer) and writes a draft to `data/form-draft.json`.
**Check every mapping**, then merge it into `config/forms.json` under a form id
that your puzzle rules reference.

A form needs at least one `success` signal — a selector, some text, or a URL
fragment that only appears once the entry is accepted. Without it the tool
cannot tell a lodged entry from a silent failure, and it will refuse to record
one as submitted.

## Calibrating the parser

Magazine layouts move around, and this is the part most likely to need a nudge
on a real issue. To see exactly what the parser sees:

```bash
npm run cli -- inspect data/inbox/take5-issue-31.pdf --page 44
```

It prints each detected grid — `##` blocked, `*x` shaded, `.` empty — plus the
text lines and which puzzles were recognised, with warnings. Shaded squares
matter: they are the letters that spell the prize answer, so if they come back
empty the entry has nothing to submit.

Tune detection in `config/puzzles.json`: each rule is a heading pattern, the
puzzle kind it introduces, and the form its entry goes to. Add rules there
rather than editing `src/parse/detect.ts`.

## How the puzzles are solved

| Puzzle | Method | Needs network |
|---|---|---|
| Sudoku | bitmask backtracking, MRV ordering; also checks the answer is unique | no |
| Wordsearch | 8-direction search; the leftover letters are the answer | no |
| Code Cracker | constraint search over word slots, bijective code↔letter map | no |
| Kriss Kross | slot/word backtracking with fewest-candidates-first | no |
| Word wheel | dictionary filtered by letter multiset, must use the centre | no |
| Crossword | clue candidates from Gemini, **vetoed by the grid** | yes |
| Trivia | Gemini, capped at 0.7 confidence because nothing can check it | yes |

The crossword solver is worth understanding: Gemini is asked for several ranked
candidates per clue and they are treated as hypotheses, not answers. The grid
throws out any that don't cross correctly. Where the oracle is no help the fill
falls back to dictionary words and the reported confidence drops below the
default floor, so those entries are held back instead of posted.

## Layout

```
src/
  parse/    pdf.ts      text runs + filled rectangles out of a PDF
            layout.ts   rectangles -> lattices (open / blocked / shaded cells)
            detect.ts   recipe-driven puzzle recognition
  solve/    one module per puzzle type, plus the Gemini clue oracle
  entry/    submit.ts   Playwright driver, guardrails, screenshots
            ledger.ts   append-only record of everything lodged
            recorder.ts drafts a form spec from a live page
  schedule/ weekly.ts   the unattended cron job
  server.ts             localhost API behind the dashboard
```

`npm test` runs the lot. The parser tests build a synthetic PDF with real
rectangles and text, so `parse/` is exercised against actual PDF bytes rather
than mocks.

## Dashboard

`npm run serve` exposes a localhost-only API on `127.0.0.1:4173`; the Take 5 tab
in the Quest reader app talks to it. It binds to loopback deliberately — it can
submit competition entries and it holds your address.
